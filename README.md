# Loan Risk Assessment — ML Project

**Problem:** When a bank gives a loan, some borrowers fail to repay (default). Lending to a defaulter costs the bank money; rejecting a good borrower costs it business. This project trains a machine-learning model that reads a loan application and predicts the **probability that the applicant will default**, so applications can be sorted into *Approve / Manual Review / Reject* bands.

**Type:** Binary classification · **Best model ROC-AUC: 0.815** · Built with Python, pandas, scikit-learn

---

## Dataset

Real borrower-level lending data is confidential — banks never publish it. So the dataset (5,000 applicants) is **generated by a documented statistical model** in `generate_data.py`, built from the same risk factors real lenders use, with realistic noise. Default rate: **28.4%**.

| Feature | Meaning |
|---|---|
| `age` | Applicant age (21–65) |
| `annual_income` | Yearly income (₹) |
| `employment_years` | Years in current employment (job stability) |
| `employment_type` | Salaried / Self-Employed / Business |
| `credit_score` | Credit score, 300–900 |
| `existing_loans` | Number of loans already running |
| `loan_amount` | Requested loan amount (₹) |
| `loan_tenure_months` | Repayment period |
| `loan_purpose` | Home / Education / Personal / Business / Vehicle / Medical |
| `debt_to_income_ratio` | Share of income already going to debt payments |
| **`default`** (target) | **1 = defaulted (high risk), 0 = repaid** |

A few values are deliberately missing (credit score, employment years) so the pipeline's missing-value handling is exercised, like real data.

## Approach

1. **Preprocessing** (one scikit-learn `Pipeline`, so no data leakage):
   - Numeric features → median imputation + standard scaling
   - Categorical features → most-frequent imputation + one-hot encoding
2. **Models compared:** Logistic Regression, Random Forest, Gradient Boosting
3. **Split:** 80/20 stratified train/test + 5-fold cross-validation
4. **Metric that matters:** ROC-AUC (ranking defaulters above good borrowers), plus precision/recall on the defaulter class — accuracy alone is misleading on imbalanced data.

## Results (held-out test set, 1,000 applicants)

| Model | ROC-AUC | Accuracy | Recall (defaulters caught) |
|---|---|---|---|
| **Logistic Regression** ✅ | **0.814** | 0.784 | 0.465 |
| Gradient Boosting | 0.809 | 0.785 | 0.472 |
| Random Forest | 0.801 | 0.785 | 0.426 |

Best model 5-fold CV ROC-AUC: **0.815 ± 0.017** — consistent, not a lucky split.

**Top risk drivers** (permutation importance): 1) debt-to-income ratio, 2) credit score, 3) loan amount, 4) annual income — exactly the factors a human loan officer checks first.

**Honest limitation:** at the default 0.5 cut-off the model catches ~47% of defaulters. In banking, a missed defaulter costs far more than a wrongly rejected good applicant, so in production you would *lower* the decision threshold (trade precision for recall). `predict.py` therefore returns a probability with risk bands instead of a bare yes/no.

## Web app (frontend + backend)

A full web version lives in `webapp/` — a Flask backend serving a polished
single-page frontend:

```bash
cd webapp
python3 app.py             # then open http://127.0.0.1:5000
```

- **Frontend** (`webapp/static/`): applicant form with sliders for credit score
  and debt-to-income, one-click *Safe / Risky sample* buttons for demos, an
  animated risk gauge, colour-coded LOW / MODERATE / HIGH verdict, and a
  key-factors list explaining the score.
- **Backend API** (`webapp/app.py`):
  - `GET  /api/health` — server + model status
  - `GET  /api/model-info` — model name, ROC-AUC, feature list
  - `POST /api/predict` — validated JSON in → risk %, category, recommendation, factors
- **Robustness:** every input is validated (presence, type, range, allowed
  values). Bad input returns a clean `400` JSON error — no crashes, no stack
  traces. Verified end-to-end: 15 test cases (valid safe/moderate/risky
  applicants + 8 error cases) all pass.

## How to run (CLI version)

```bash
pip install -r requirements.txt
python3 generate_data.py   # creates data/loan_data.csv
python3 train.py           # trains, compares, saves best model + charts
python3 predict.py         # scores a sample applicant
```

Score your own applicant:

```bash
python3 predict.py --age 32 --annual-income 850000 --employment-years 6 \
  --employment-type Salaried --credit-score 742 --existing-loans 1 \
  --loan-amount 500000 --loan-tenure-months 36 --loan-purpose Personal \
  --debt-to-income-ratio 0.28
# -> Default risk probability: 7.4%  |  LOW  |  APPROVE
```

## Viva / interview questions this project answers

1. **Why Logistic Regression over Random Forest here?** It scored the best ROC-AUC, and it is interpretable — each coefficient says how a factor moves the risk, which banks and regulators demand.
2. **Why ROC-AUC and not accuracy?** With only ~28% defaulters, a lazy model predicting "everyone repays" already gets ~72% accuracy while catching zero defaulters. AUC measures ranking quality across all thresholds.
3. **How did you avoid data leakage?** Imputation, scaling and encoding live inside the `Pipeline`, so they are fitted only on training data.
4. **Why is recall of defaulters low, and what would you do?** Class imbalance + a 0.5 threshold. Lower the threshold, or use class weights / SMOTE — and choose based on the bank's cost of a missed default vs a lost customer.
5. **Why is `existing_loans` importance low when it obviously matters?** Its effect is already carried by the debt-to-income ratio (correlated features share importance).
6. **Why synthetic data?** Real borrower data is confidential; the generator uses the documented factors lenders actually use, with noise, so the model learns realistic patterns.
